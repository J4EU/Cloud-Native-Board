# v1.0.0 Requirements

## 목표

`v1.0.0`의 목표는 F1 Board를 단일 EC2 환경에 재현 가능하게 배포하는 것이다.

현재는 단일 EC2에 Docker Compose 기반으로 애플리케이션을 실행하고, Nginx Reverse Proxy를 구성하는 데 성공했다.

하지만 아직 아래 작업들은 수동으로 처리하고 있다.

- EC2 접속 후 GitHub Repository clone
- Docker Compose v2 / Buildx 등 Docker 실행 환경 준비
- 환경 변수 파일 생성
- DB 컨테이너 접속 후 초기 SQL 실행
- Docker Compose 실행

따라서 `v1.0.0`에서는 `terraform apply` 이후 EC2 초기 설정부터 애플리케이션 실행까지 최대한 자동화하는 것을 목표로 한다.

---

## v1.0.0 기준

`v1.0.0`은 단순히 “EC2에 한 번 배포해본 상태”가 아니라, 같은 구조를 다시 만들 수 있는 단일 EC2 배포 상태를 의미한다.

구성 목표는 다음과 같다.

```text
Terraform
→ EC2 생성
→ user_data 실행
→ Docker 실행 환경 구성
→ Repository clone
→ 환경 변수 주입
→ DB 초기화
→ Docker Compose 실행
→ 서비스 접속 가능
```

---

## 구현 범위

### 1. EC2 초기 설정 자동화

- [ ] EC2 생성 시 `user_data`가 실행되도록 구성한다.
- [ ] Git을 자동 설치한다.
- [ ] Docker Engine을 자동 설치한다.
- [ ] Docker Compose v2를 사용할 수 있도록 구성한다.
- [ ] Docker Buildx를 사용할 수 있도록 구성한다.

### 2. 애플리케이션 배포 자동화

- [ ] EC2 내부에 배포 디렉터리를 생성한다.
- [ ] GitHub Repository를 자동으로 clone한다.
- [ ] 애플리케이션 실행에 필요한 환경 변수 파일을 생성한다.
- [ ] Docker Compose로 frontend, backend, database 컨테이너를 실행한다.

### 3. DB 초기화 자동화

- [ ] 초기 schema를 SQL 파일로 관리한다.
- [ ] DB 컨테이너 최초 실행 시 SQL 파일이 자동 실행되도록 구성한다.
- [ ] 수동으로 DB 컨테이너에 접속해 쿼리를 실행하지 않도록 한다.

### 4. Nginx Reverse Proxy 유지

- [ ] 외부 요청은 Nginx를 통해 처리한다.
- [ ] `/api/*` 요청은 backend 컨테이너로 전달한다.
- [ ] backend 포트는 외부에 직접 노출하지 않는다.

---

## 완료 기준

- [ ] `terraform apply` 이후 EC2가 생성된다.
- [ ] EC2 초기 부팅 과정에서 Docker 실행 환경이 자동으로 준비된다.
- [ ] Repository가 자동으로 clone된다.
- [ ] 환경 변수 파일이 자동으로 생성된다.
- [ ] DB 초기화 SQL이 자동 실행된다.
- [ ] Docker Compose로 전체 서비스가 실행된다.
- [ ] 브라우저에서 게시판 페이지에 접근할 수 있다.
- [ ] 게시글 조회 API가 정상 동작한다.
- [ ] backend 포트가 외부에 직접 노출되지 않는다.
